# Две роли — регистрация и вход

Небольшой учебный сайт на обычных HTML, CSS и JavaScript. Серверная часть — одна функция Vercel (`api/auth.js`). Данные хранятся в PostgreSQL (Neon). На сайте можно создать **одну пользовательскую** и **одну администраторскую** учётную запись. Для каждой роли нужен свой код приглашения. Роли пока только отображаются; права доступа будут настроены в следующей лабораторной.

## Как пользоваться

1. Откройте сайт и выберите «Регистрация».
2. Укажите почту, свой пароль длиной от 8 символов, роль и соответствующий код приглашения.
3. После регистрации откроется личный кабинет. Кнопка «Выйти» завершает сеанс.
4. На вкладке «Вход» можно снова войти по почте и паролю.

Для каждой роли регистрация разрешена только один раз. Коды приглашения передаются владельцу отдельно и не хранятся в GitHub.

## Как работает код — объяснение для защиты

### 1. Разметка (`index.html`)

Тег `<form id="auth-form">` собирает почту и пароль. Блок `register-fields` содержит роль и код приглашения и показывается только при регистрации. `profile-panel` сначала скрыт атрибутом `hidden`. После успешного ответа сервера он показывается. `label` связан с полем через `for` и `id` — так удобнее пользоваться формой и программами чтения экрана.

### 2. Стили (`style.css`)

`.layout` делит страницу на две колонки: описание слева, форма справа. `.card` оформляет форму. Правило `@media(max-width:850px)` переводит колонки в одну на узких экранах. Цвета и отступы заданы обычным CSS; библиотека интерфейса не нужна.

### 3. Логика браузера (`script.js`)

Переменная `mode` хранит текущую вкладку: `login` или `register`. Функция `setMode` переключает вкладки и поля. Обработчик `submit` отменяет обычную перезагрузку страницы (`event.preventDefault()`), собирает данные формы и отправляет JSON через `fetch` на `/api/auth`. Если сервер отвечает успехом, `showProfile` показывает личный кабинет. При загрузке страницы запрос `?action=me` проверяет, осталась ли действительная сессия. При выходе браузер отправляет `?action=logout`.

### 4. Сервер (`api/auth.js`)

Vercel запускает этот файл как серверную функцию. Значение `action` в адресе определяет действие:

- `register`: проверяет формат почты, длину пароля, роль и код приглашения; записывает аккаунт в базу;
- `login`: ищет аккаунт по почте и проверяет пароль;
- `me`: проверяет cookie и возвращает почту и роль;
- `logout`: удаляет cookie.

Пароль не записывается открытым текстом: `scryptSync` создаёт хеш с отдельной случайной солью для каждого аккаунта. При входе функция вычисляет хеш снова и сравнивает через `timingSafeEqual`. SQL-запросы используют подстановку `${...}` через библиотеку Neon, поэтому пользовательский ввод передаётся как параметр запроса.

После входа сервер выдаёт cookie `lab_session`. В ней находится ID аккаунта и срок действия, подписанные секретом `SESSION_SECRET` через HMAC. `HttpOnly` запрещает JavaScript читать cookie, `Secure` отправляет её только по HTTPS, `SameSite=Lax` ограничивает передачу с других сайтов. Сервер проверяет подпись, срок действия и наличие аккаунта в базе.

### 5. База (`schema.sql`)

Таблица `accounts` содержит ID, почту, хеш пароля, роль и дату создания. `UNIQUE` у почты запрещает повтор адреса. `UNIQUE` у роли гарантирует максимум одного пользователя и одного администратора, даже если два человека одновременно отправят форму. `CHECK` разрешает только значения `user` и `admin`.

### Важный пример потока

**Регистрация:** браузер отправляет форму → функция проверяет код → пароль превращается в хеш → запись сохраняется в базе → сервер выдаёт cookie → открывается кабинет.

**Вход:** браузер отправляет почту и пароль → функция находит запись → сравнивает хеш → выдаёт cookie → открывается кабинет.

## Запуск своего экземпляра

1. Создайте базу PostgreSQL и выполните `schema.sql`.
2. Создайте проект Vercel из этого репозитория. Framework Preset: **Other**. Root Directory: корень репозитория.
3. В настройках Vercel добавьте `DATABASE_URL`, `SESSION_SECRET`, `USER_INVITE_CODE`, `ADMIN_INVITE_CODE`. Используйте длинные случайные значения для последних трёх. Не добавляйте `.env` в GitHub.
4. Разверните проект. Для локальной разработки установите зависимости (`npm install`), создайте `.env.local` по примеру `.env.example` и запустите `npx vercel dev`.

## Границы этой лабораторной

Есть две роли, регистрация, вход, выход и личный кабинет. Разные права для ролей и защищённые страницы пока не реализованы: это задача следующей лабораторной. В учебной версии также нет восстановления пароля и защиты от большого числа попыток входа; перед использованием в реальном сервисе их нужно добавить.
