# Лист — регистрация и авторизация

Сайт: https://two-roles-auth-lab.vercel.app/

## Как пользоваться

**Регистрация:** имя и фамилия → почта → свой пароль (от 8 символов) → «Зарегистрироваться» → код из письма → кабинет. После подтверждения в базе сохраняются имя, почта, хеш пароля, роль и дата создания. Письмо приходит на адрес, который указал посетитель. Код действует 10 минут; не больше 5 попыток ввода, повторная отправка через минуту.

**Последующий вход:** почта → сохранённый пароль → выбор «Пользователь» или «Администратор» → «Войти». Письмо при обычном входе не требуется. Неверный пароль отклоняется, несоответствие выбранной роли настоящей роли аккаунта тоже отклоняется. Выйти можно кнопкой в кабинете.

**Две роли:** посетители регистрируются пользователями. Первый администратор определяется адресом из серверной настройки ADMIN_EMAIL после подтверждения почты. Других администраторов назначает действующий администратор через кабинет. Выбор «Администратор» при входе не меняет роль. Можно создавать сколько угодно пользовательских аккаунтов. Кабинеты имеют разные заголовки, управление назначением администраторов уже доступно; остальные права доступа — следующая лабораторная.

Если вы входили в предыдущей версии только по коду, у вас ещё нет пароля сайта: один раз пройдите регистрацию с именем и паролем, подтвердите почту. Существующий аккаунт сохранит свой ID. Повторная регистрация обычного аккаунта с уже установленным паролем запрещена.

## Где сохраняются данные

Постоянная база PostgreSQL размещена в Neon, серверная функция — в Vercel. Закрытие страницы и перезапуск браузера не удаляют аккаунт. На GitHub хранится код, а не база пользователей и не секретные пароли. Cookie хранит сеанс текущего браузера, а не сам аккаунт.

## Разбор HTML и CSS

form собирает данные. label связан с input через for/id. type=email проверяет формат почты в браузере. minlength и maxlength задают длину ввода; сервер повторно проверяет значения. type=password скрывает символы. select позволяет выбрать тип входа. Поле имени отображается при регистрации, выбор роли — при входе. hidden скрывает неактивные блоки.

CSS Grid делит страницу на две колонки. Media query при ширине меньше 850 пикселей располагает блоки вертикально. Классы card, primary, tabs оформляют карточки, кнопки и вкладки. Селектор [hidden] гарантирует скрытие неактивных блоков.

## Разбор script.js

$ — сокращение для document.querySelector. mode хранит вкладку login/register. confirming указывает, ожидаем ли мы код подтверждения регистрации.

setMode сбрасывает форму и переключает поля, подписи и атрибут required. showProfile выводит имя, почту, роль и соответствующий заголовок кабинета. textContent вставляет эти данные как текст, а не как HTML.

api отправляет JSON через fetch методом POST и проверяет код ответа. Обработчик onsubmit отменяет обычную перезагрузку через preventDefault, собирает FormData и отправляет действие login, register или verify. После register показывается поле кода, введённый пароль очищается в браузере. После verify или login открывается кабинет. try/catch/finally показывает ошибку и восстанавливает кнопку.

При загрузке GET action=me проверяет сессию и восстанавливает кабинет. Кнопка выхода вызывает action=logout и возвращает форму входа.

## Разбор api/auth.js

Файл исполняется на сервере Vercel. process.env получает секреты из настроек Vercel. Браузер не получает строку подключения к базе и пароль Gmail.

### Пароль

hashPassword создаёт случайную соль (randomBytes), затем вычисляет scrypt-хеш. Соль и хеш сохраняются вместе. Одинаковые пароли имеют разные хеши благодаря соли. checkPassword повторяет вычисление с сохранённой солью и сравнивает результат через timingSafeEqual. Открытый пароль не записывается в базу.

### Регистрация — action=register

Сервер проверяет имя, почту и длину пароля. Если полноценный аккаунт уже существует, возвращает ошибку 409. Лимит запросов хранится в базе: до 10 запросов отправки за час для IP, а на одну почту не чаще раза в минуту.

randomInt генерирует шестизначный код. В login_codes временно записываются имя, хеш пароля, HMAC кода, срок действия и число попыток. Nodemailer отправляет письмо через защищённое SMTP-соединение Gmail. При ошибке отправки сервер возвращает ошибку и делает код недействительным.

### Подтверждение — action=verify

Сервер проверяет шесть цифр, срок и число попыток. Атомарный UPDATE учитывает попытку и погашает правильный код, поэтому использовать его повторно нельзя. После подтверждения создаётся запись accounts. Роль вычисляется сервером по ADMIN_EMAIL; значение role из формы регистрации не используется.

Запись старой версии с меткой email-code может получить имя и пароль только после подтверждения почты. Готовый пароль существующего аккаунта этой процедурой заменить нельзя.

### Вход — action=login

Сервер находит аккаунт по почте и проверяет хеш введённого пароля. Затем сравнивает выбранную роль с сохранённой. При несовпадении возвращает 403. Выбор роли не выдаёт новых прав. На один адрес допускается 20 попыток входа за 15-минутное окно.

### Сессия

finishLogin формирует ID аккаунта и время истечения, кодирует их в base64url и подписывает HMAC-SHA256 с SESSION_SECRET. Base64 не шифрует, а кодирует; подпись позволяет обнаружить подмену. Cookie lab_session действует сутки: HttpOnly не даёт JavaScript прочитать её, Secure требует HTTPS, SameSite=Lax ограничивает передачу с других сайтов.

readSession проверяет подпись и срок действия. action=me после проверки читает имя, почту и роль из базы. action=logout удаляет cookie текущего браузера. Cache-Control: no-store запрещает кэшировать ответы с данными аккаунта. POST дополнительно проверяет Origin.

SQL-подстановки Neon передают значения параметрами. Поэтому почта или имя пользователя не становятся исполняемой частью SQL-запроса.

## Таблицы базы

**accounts:** id, name, email (уникальный), password_hash, role, created_at. Это постоянные аккаунты.

**login_codes:** email, code_hash, expires_at, sent_at, attempts, pending_name, pending_hash. Это незавершённые регистрации. Название таблицы осталось от прошлой версии; сейчас код подтверждает регистрацию.

**mail_limits:** bucket и total — счётчики запросов. Bucket содержит HMAC адреса/IP и временного окна. Для долгой эксплуатации нужна периодическая очистка старых записей.

## Настройка

Выполнить schema.sql в PostgreSQL, создать проект Vercel с Framework Preset Other и добавить DATABASE_URL, SESSION_SECRET, SMTP_USER, SMTP_PASS, ADMIN_EMAIL. SMTP_PASS — пароль приложения Google. Настоящие значения не записывать в GitHub. Для локальной разработки установить зависимости npm install и использовать npx vercel dev с локальными переменными окружения.

## Ограничения

Подробные разрешения по ролям — следующая лабораторная. Пока нет восстановления пароля и выхода со всех устройств. Доставка зависит от Gmail, письмо может попасть в спам. Лимиты по IP могут затронуть общую сеть. Это учебный проект, а не готовая промышленная система управления пользователями.

## Как назначить нового администратора

Новый человек сначала регистрируется обычным пользователем и подтверждает почту. Действующий администратор входит в свой кабинет, открывает список пользователей и нажимает «Назначить администратором» напротив нужной почты. Перед сохранением сайт просит подтвердить действие. Новый администратор затем выбирает «Администратор» при входе. Если он уже вошёл, обновление страницы подтянет новую роль.

Первый администратор создаётся по ADMIN_EMAIL. Последующие назначаются через кабинет и хранят свою роль в accounts. Каждый администратор может назначать следующих. Администратор также может нажать «Снять права администратора», чтобы вернуть другому аккаунту роль пользователя. С себя и владельца сайта (ADMIN_EMAIL) права снять нельзя. Сервер проверяет роль при каждом административном запросе, поэтому снятие прав действует и для уже открытой сессии.

В api/auth.js действия users и promote сначала проверяют подписанную сессию, затем читают актуальную роль вызывающего из базы. Обычный пользователь получает 403 даже при прямом запросе API. users возвращает последние 200 аккаунтов без паролей и кодов. promote изменяет только поле role выбранного зарегистрированного аккаунта. Пароль менять и повторно регистрироваться не нужно.

В script.js loadUsers создаёт строки списка через textContent. Список виден в администраторском кабинете; защита обеспечивается серверной проверкой, а не скрытием кнопки. На защите: «Администратора назначает существующий администратор. Самостоятельно выбрать такую роль при регистрации нельзя».
