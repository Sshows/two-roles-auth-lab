# Лист — вход по коду из письма

Сайт: https://two-roles-auth-lab.vercel.app/

## Что делает посетитель

1. Открывает «Вход» или «Регистрация» и вводит свою почту.
2. Нажимает «Получить код». Сайт отправляет письмо на этот адрес.
3. Вводит 6 цифр из письма и нажимает «Подтвердить и войти».
4. При первом входе создаётся аккаунт, при следующих открывается существующий.
5. В кабинете видны почта, роль и кнопка выхода.

Постоянный пароль и приглашение больше не нужны. Вкладки входа и регистрации используют один механизм: подтверждение владения почтой. Код действует 10 минут, используется один раз, допускает не больше 5 попыток. Повторная отправка на тот же адрес доступна через минуту. Проверяйте папку «Спам».

Есть две роли, а количество пользователей не ограничено двумя. Почта из серверной настройки ADMIN_EMAIL получает роль администратора после подтверждения кодом. Остальные получают роль пользователя. Посетитель не может выбрать себе администратора. Разные права доступа — следующая лабораторная.

## Объяснение HTML и CSS

HTML задаёт элементы страницы. Атрибут id позволяет JavaScript находить конкретное поле. label связывает подпись с полем. type=email включает базовую проверку почты браузером. У поля кода inputmode=numeric показывает цифровую клавиатуру на телефоне, pattern задаёт шесть цифр. Атрибут hidden скрывает поле кода и кабинет до нужного шага.

CSS задаёт цвета, шрифт, отступы и расположение элементов. Grid делит страницу на две колонки. Media query при ширине меньше 850 пикселей располагает блоки друг под другом. [hidden] гарантирует скрытие неактивных блоков.

## Объяснение script.js

Функция $ — короткая запись document.querySelector: найти элемент страницы по селектору. step содержит send (отправка письма) или verify (проверка кода). mode отвечает только за заголовок вкладки.

resetForm возвращает форму к вводу почты. showProfile скрывает форму и показывает данные аккаунта. setMode меняет вкладку и сбрасывает незавершённый ввод. api отправляет POST-запрос с JSON и превращает ответ с ошибкой в исключение.

Обработчик onsubmit отменяет стандартную перезагрузку страницы через preventDefault. FormData собирает поля формы. На первом шаге отправляется action=send, затем показывается поле кода. На втором шаге отправляется action=verify, после успеха открывается кабинет. try/catch/finally показывает ошибку и всегда возвращает кнопку в рабочее состояние.

При загрузке страницы запрос action=me проверяет сессию. Кнопка выхода вызывает action=logout. Данные аккаунта вставляются через textContent, поэтому текст почты не исполняется как HTML.

## Объяснение api/auth.js

Это серверная функция Vercel. Браузер не получает SMTP-пароль, строку подключения к базе и секрет подписи: они читаются из process.env на сервере.

neon создаёт клиент PostgreSQL. Nodemailer подключается к smtp.gmail.com по защищённому соединению на порту 465. sign вычисляет HMAC-SHA256 с серверным секретом. Такая подпись используется для кодов и сессий.

### action=send

Сервер проверяет почту, затем увеличивает счётчик отправок для IP и текущего часового окна. Лимит — 10 запросов за час. IP хранится в виде HMAC, а не открытым текстом. randomInt криптографически случайно выбирает шестизначный код. В login_codes записываются HMAC от почты и кода, время истечения, время отправки и число попыток. Сам код в базе не хранится.

INSERT ... ON CONFLICT обновляет запись для уже известной почты. Условие WHERE запрещает повторную отправку чаще раза в минуту. Nodemailer отправляет письмо. Если почтовый сервер отказал, код становится недействительным и посетитель видит ошибку; сайт не сообщает об успешной отправке.

### action=verify

Сервер проверяет формат кода и вычисляет его HMAC. Один UPDATE одновременно учитывает попытку и погашает совпавший код. Это защищает от повторного использования и двух одновременных входов с одним кодом. Просроченный код или больше пяти попыток не принимаются.

После подтверждения почты сервер определяет роль по ADMIN_EMAIL. INSERT ... ON CONFLICT создаёт аккаунт или возвращает существующий. SQL-подстановки библиотеки Neon передают пользовательский ввод параметрами, а не частью SQL-команды.

### Сессия и выход

Сервер кодирует ID аккаунта и срок действия в base64url, затем подписывает их HMAC. Base64 — кодирование, не шифрование. Подпись не позволяет незаметно изменить ID или срок. Cookie lab_session действует сутки. HttpOnly запрещает JavaScript читать её, Secure требует HTTPS, SameSite=Lax ограничивает передачу с других сайтов. Сервер дополнительно проверяет Origin для POST-запросов.

readSession проверяет формат, подпись через timingSafeEqual и срок действия. action=me получает аккаунт из базы только после этих проверок. action=logout очищает cookie браузера. Cache-Control: no-store запрещает кэшировать ответы с данными аккаунта.

## Таблицы

accounts: ID, уникальная почта, роль, дата создания. Поле password_hash осталось для совместимости с предыдущей версией и содержит метку email-code у новых аккаунтов; пароль пользователя здесь больше не используется.

login_codes: последний код для каждой почты в виде HMAC, срок, время отправки, число попыток.

mail_limits: счётчики запросов по IP и часовому окну. Для долгой эксплуатации стоит добавить периодическую очистку старых счётчиков.

## Настройка своего экземпляра

1. Выполнить schema.sql в PostgreSQL.
2. Создать проект Vercel, Framework Preset — Other.
3. Добавить секретные переменные DATABASE_URL, SESSION_SECRET, SMTP_USER, SMTP_PASS и ADMIN_EMAIL.
4. SMTP_USER — адрес Gmail отправителя, SMTP_PASS — его пароль приложения Google, ADMIN_EMAIL — адрес администратора сайта.
5. Опубликовать проект. Не помещать настоящие секреты в репозиторий.

## Ограничения

Доставка зависит от Gmail и может задерживаться или попадать в спам. Это учебная реализация: нет глобального выхода со всех устройств, CAPTCHA и развитой системы прав. Удаление cookie завершает вход только в текущем браузере. Счётчик по IP может затронуть несколько людей в общей сети. Код не является вторым фактором: это самостоятельный способ входа через почту.
